# 悬浮标 MCP 服务

让 Claude Code 借用你已经登录好的 ChatGPT / Gemini —— 写代码卡在某个判断上时，
让另一家模型出个第二意见，再跟自己的结论对一下。**走的是你已经付过钱的订阅，不花 API 的钱。**

## 接进 Claude Code

先在悬浮标的托盘菜单里打开 **「允许本机程序调用」**，然后：

```bash
claude mcp add xuanfubiao -- node "D:/Claude_projects/01_悬浮标/tools/mcp-server/server.js"
```

不需要 `npm install`，也不需要配密钥 —— 它会自己去
`%APPDATA%\XuanFuBiao\api-token.txt` 读。

要手动指定密钥就设环境变量 `XFB_API_TOKEN`。

## 四个工具

| 工具 | 干什么 |
|---|---|
| `ask_chatgpt` | 问 ChatGPT 网页端，等它生成完，返回正文 |
| `ask_gemini` | 问 Gemini 网页端 |
| `ask_both` | 同一个问题同时问两家，两份回答一起拿回来对照 |
| `list_ai_targets` | 列出当前能投递的目标；连不上时也用它确认状态 |

## 几件得先知道的事

- **一次只能跑一个。** 投递要占剪贴板，所以第二个请求会排队等第一个跑完。
  这不是没优化，是下层的物理限制（详见主 README 的〈两个关键取舍〉）。
- **只能用网页端目标。** 桌面端投递要闪切前台焦点，被一个后台程序随时驱动的话，
  你正在打字时会毫无预兆地被抢走键盘。所以接口那一端根本不开放桌面端。
- **要等几十秒。** 对面是真的在生成，没有流式，只能等它讲完。
- **对面看不到这边的对话。** 问题要自带上下文。
- 它会真实占用你的 ChatGPT 会话，那条问答会出现在你自己的对话历史里。

## 验一下通没通

```bash
XFB_API=1 pnpm dev            # 一个终端
node tools/api-selftest.js    # 另一个终端
```

自检不会往你的真实对话里发任何东西 —— 它自己假扮扩展，回一段编出来的答案，
验的是那段文字有没有沿着整条链路原样传回来。
